# S01 — Project scaffold: deployable Worker skeleton

**Epic:** scaffolding · **Depends on:** nothing · **Spec refs:** [08-tech-stack](../specs/08-tech-stack.md), [01-architecture](../specs/01-architecture.md)

> As a developer, I want a typed, tested, manually-deployable Worker skeleton, so that every later story lands on rails instead of yak-shaving.

## Description

The repo becomes a working TypeScript Cloudflare Worker project with the exact version pins, config shapes and directory layout from spec 08: `wrangler.jsonc` (assets binding, KV, both scheduled Workflows with their cron `schedules`, `BASE_URL` var), Hono entry point with `/api/health`, skeleton `WorkflowEntrypoint` classes for `refresh-weather` and `refresh-campsites`, the two-project vitest setup (unit + workers pool, **post-0.13 API**), generated `Env` types, and the secret/`.dev.vars` convention. Ends with the first real manual deploy.

## Acceptance criteria

- [x] `package.json` pins the spec-08 versions; `npm install` is clean on Node 22 LTS; `npm run check` (tsc + both vitest projects) and `npm test` scripts exist.
- [x] `wrangler.jsonc` matches the spec-08 shape: `run_worker_first: ["/api/*", "/mcp", "/mcp/*"]`, `ASSETS` + `KV` bindings, both Workflows (`refresh-weather` 2-hourly, `refresh-campsites` weekly) with `schedules` on their bindings, `observability` enabled, `BASE_URL` var, `nodejs_compat`; `worker-configuration.d.ts` generated by `wrangler types` and committed.
- [x] `src/` skeleton follows the spec-01 tree (empty `core/ports/adapters/delivery/workflows` directories may hold only placeholder modules); `src/index.ts` exports `fetch` (Hono) as `satisfies ExportedHandler<Env>` and re-exports both `WorkflowEntrypoint` classes.
- [x] One unit-project test passes (trivial pure function) and one worker-project test passes: `GET /api/health` via `exports.default.fetch` returns `{ ok: true }`, and a KV put/get round-trips via `env.KV` — proving the pool, bindings and config path all work.
- [x] Worker-project tests create one instance of each Workflow via its binding and, using `introspectWorkflowInstance`, see it reach `complete` with the skeleton output (single no-op step — real steps land in S04/S06).
- [x] `.dev.vars` is git-ignored and documented; no secret value appears anywhere in the repo.
- [x] **First manual deploy performed**: `wrangler deploy` succeeds; `https://tjaldur.9z.is/api/health` returns 200 `{ ok: true }` (custom domain on the owner's `9z.is` zone — decided 2026-06-12, supersedes workers.dev); the URL is recorded in this story's notes and set as `BASE_URL`.

## Demo

Clone → `npm install` → `npm run check` green → `npx wrangler deploy` → `/api/health` live at tjaldur.9z.is.
